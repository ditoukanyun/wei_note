# 配置中心演示手册

## 与详稿的时间衔接

本手册支持 [[配置中心分享讲稿]] 的第 06、07 节：正常变更约 5 分钟，异常、环境隔离与回滚约 4 分钟。其余原理和源码走读在详稿中完成，不把安装和网络等待计入分享时长。

每次操作都先提出预期，再核对业务响应和实例状态，最后解释原因。特别保留以下问题：两个开发实例是否一致、测试是否保持原值、配置已收到但被拒绝时业务应怎样表现。无人回答时由讲师给出推演，不留空等候。

## 启动与验证

在本目录的 `案例/` 中执行：

```bash
docker compose up -d --build
docker compose run --rm verify
```

宿主机只需 Docker 与 Compose v2。首次构建需联网，建议为 Docker 分配至少 3 GB 内存。构建运行 3 项配置测试，验证容器检查真实配置刷新和列表行为，并恢复初始配置。

| 入口 | 默认地址 |
| --- | --- |
| 配置演示台 | http://localhost:8081/ |
| 开发实例乙的业务接口 | http://localhost:8082/api/orders |
| 测试实例的业务接口 | http://localhost:8083/api/orders |
| Nacos 原生控制台 | http://localhost:8848/nacos/ |

案例只包含 Nacos、初始化服务和三个 Java 应用，不需要数据库与任务组件。Nacos 为本地教学环境，关闭鉴权且端口只映射到本机。

## 现场步骤

1. 点击“恢复初始配置”，等开发甲、乙变成关闭 / 100，测试变成关闭 / 7。
2. 观察三个实例的配置版本和启动标识，列表返回 0 笔。
3. 发布开发环境开启 / 3。
4. 两个开发实例显示每页 3，列表返回 3 笔，启动标识不变。
5. 打开测试接口，仍关闭且返回 0 笔。
6. 在 Nacos 页面选择开发 Namespace `share-dev`，Group `ORDER_SERVICE`，Data ID `order-list.yaml`。
7. 将 `page-size` 改为 2，发布后列表返回 2 笔。
8. 将页大小改为 0，发布后显示拒绝原因，列表仍按上次有效值返回。
9. 恢复合法值，再演示测试 Namespace `share-test` 中的同名配置保持独立。

页面自己每两秒刷新显示；后台 Java 客户端通过 Nacos SDK 接收配置，不依赖页面轮询才能刷新。

## 备用命令

```bash
curl http://localhost:8081/api/runtime
curl http://localhost:8081/api/orders
curl -X POST http://localhost:8081/api/config/dev -H 'Content-Type: application/json' -d '{"enabled":true,"pageSize":3}'
```

Windows PowerShell 使用 `curl.exe`。发布 API 会提前校验；非法配置演示需通过 Nacos 原生控制台修改。

## 排查与停止

```bash
docker compose ps -a
docker compose logs --tail 80 app-a app-b config-init
docker compose down
```

`config-init` 退出码为 0 是正常完成。端口占用时，将 `.env.example` 复制为 `.env` 后调整端口。

普通停止保留数据卷；需要完全重建本案例配置时执行 `docker compose down -v`，它会删除本项目的演示数据卷。

## 离线迁移

在与公司电脑同架构的联网电脑构建后导出：

```bash
docker image save -o config-share-images.tar java-config-share-demo:1.0.0 nacos/nacos-server:v2.5.1 python:3.12-alpine
```

将镜像文件与本篇源码包一起复制到公司电脑：

```bash
docker image load -i config-share-images.tar
docker compose up -d --no-build --pull never
```

源码包不含镜像；镜像 CPU 架构需要与目标电脑一致。Apollo 服务端未包含在本案例中，Apollo 的类比与接入说明见 [[Apollo与前端配置类比]]。

## 可选的断网与重启实验

另见 [[配置中心扩展实验与实践]]，约 8 分钟。先采用合法配置，再停止 Nacos，分别观察运行中的实例、同一容器重启、无缓存的 `app-cold` 探针。探针属于 `experiments` profile，普通启动不运行它；实验结束必须恢复 Nacos 与应用并移除探针。

本例使用的读取接口不会自动从 SDK 磁盘快照离线启动；完整操作与已验证结果以扩展文档为准。
