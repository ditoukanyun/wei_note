# learn-zk 学习文档

这套文档配合 `learn-zk` 工程使用：**每一段原理都能在代码里找到对应实现，每一段实现都能在本地跑出结果**。

文档面向两类读者：

- 会写前端 / 会写业务代码，但没系统用过 ZooKeeper；
- 用过 ZooKeeper，但只停留在「会调 `create` / `getData`」，不清楚 watch 和分布式锁为什么这么设计。

## 1. 先跑起来

```bash
docker compose up -d          # 三节点 ZK + zoonavigator
mvn spring-boot:run           # 应用，端口 8088
```

打开 <http://localhost:8088/index.html>，页面分三个页签：

| 页签 | 演示内容 |
| --- | --- |
| 节点 CRUD | 增删改查、版本乐观锁、树形浏览 |
| Watch 监听 | 注册监听、观察事件、理解「一次性」 |
| 分布式锁 | 多线程抢锁扣库存、无锁 vs 加锁对比、完整日志 |

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| znode | ZooKeeper 树上的一个节点，由「路径 + 字节数组 + Stat」组成 |
| zxid | 事务 ID，64 位，全局递增；由 epoch（高 32 位）和计数器（低 32 位）拼成 |
| Stat | znode 的元数据：版本号、创建/修改时间、子节点数、临时节点归属等 |
| session | 客户端与服务端之间的会话；临时节点的生命周期绑定它 |
| watch | 一次性的事件订阅，节点发生指定变化时服务端推送一次通知 |
| quorum | 过半节点，写操作需要 `n/2 + 1` 个节点确认 |
| ZAB | ZooKeeper 的原子广播协议，负责 Leader 选举和写请求复制 |
| ephemeral | 临时节点，会话结束自动删除 |
| sequential | 顺序节点，创建时服务端在名字后追加 10 位递增序号 |
| curator | Apache 的 ZooKeeper 客户端封装库，提供重试、连接管理和常用 recipe |
| recipe | Curator 基于 ZK 原语实现的通用组件，如分布式锁、选主、缓存 |

## 5. 文档约定

- 所有 `文件:行号` 都相对项目根目录，例如 `src/main/java/com/example/learnzk/service/ZkService.java:45`。
- 文中「实测」数据来自本机三节点集群（2185/2186/2187）的一次运行。并发实验的绝对值会随机器负载浮动，**结论（有锁不丢、无锁丢失）是稳定的**。
- 代码引用以当前仓库为准；如果改了代码，行号可能偏移，以方法名为准。
