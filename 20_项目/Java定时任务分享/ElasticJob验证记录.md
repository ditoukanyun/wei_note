日期：2026-10-21。环境：Apple 芯片 Mac、Docker Desktop、Linux arm64 容器。

- 独立 Compose 项目 `java-job-share` 构建并启动成功。
- Java 测试 4 项全部通过：失败恢复、并发幂等、事务回滚、批量与分片范围。

## 2026-10-22 分批处理实测

在同一 arm64 Docker 环境重新构建，Java 测试增加为 **6 项，失败与错误均为 0**。新增覆盖 750 笔订单三轮推进、额外执行幂等、恢复 12 笔基线，以及检测到运行分片时拒绝替换教学数据。

先运行基础 `verify`，再运行 `verify-large`，两个命令退出码均为 0。后者使用真实 PostgreSQL、ZooKeeper 和两个任务实例：

| 阶段 | 成功 / 待补偿 / 流水 |
| --- | --- |
| 750 笔载入后 | 0 / 750 / 0 |
| 第一轮 | 300 / 450 / 300 |
| 第二轮 | 600 / 150 / 600 |
| 第三轮 | 750 / 0 / 750 |
| 第四轮 | 750 / 0 / 750，订单与尝试次数未改变 |
| 清理后 | 12 笔基础订单全部待补偿，流水 0，故障注入开启 |

同时核对三个区域每轮分别推进 100、100、50 笔，两个实例实际参与执行，所有订单尝试次数为 1，每条分片调用成功数不超过 100。原始输出见 [[ElasticJob分批处理验证输出.txt]]。

步骤见 [[ElasticJob扩展实验与实践]]。本轮没有实现或演练 DataflowJob、自动重试、历史日期参数、misfire 和 failover，相关附录均标为设计推演。
