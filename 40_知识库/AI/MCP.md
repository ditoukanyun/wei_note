# MCP
MCP 是 Model Context Protocol，用于让模型通过标准协议连接外部工具、数据源和工作流。

## 相关概念
- [[MCP 服务器推荐]]
- [[Tool]]

## 工作流程

```mermaid
flowchart LR
  A[模型或客户端] --> B[MCP 协议]
  B --> C[MCP Server]
  C --> D[工具、资源或提示词]
  D --> E[外部系统]
```

## 能力边界

- Tools：让模型执行具体动作，例如查询数据库、调用 API、读写文件。
- Resources：向模型暴露可读取上下文，例如文档、配置、数据片段。
- Prompts：提供可复用的任务模板。

## 实践检查清单

- 工具参数是否有 schema 限制，避免模型传入危险参数。
- 工具是否按最小权限访问外部系统。
- 资源是否做权限隔离和敏感信息脱敏。
- 工具执行是否有日志、超时和错误返回。
- 是否区分只读工具和会产生副作用的写工具。

## 设计边界

MCP 的重点是把外部能力标准化暴露给模型，但标准化不等于无风险。每个工具都应该有明确职责、参数 schema、权限范围、超时、错误语义和审计记录。资源暴露也要控制粒度，避免把整个仓库、数据库或私有文档无差别塞进上下文。

接入 MCP 前要先问是否真的需要模型调用。若一个任务可以由确定性脚本完成，脚本更稳定；若需要模型判断何时调用、如何组合工具，MCP 才能体现价值。

团队接入 MCP 时，应把服务器配置、权限说明、示例调用和禁用场景写清楚，避免工具能力在不同成员环境里变成黑盒。

## 常见误区

- 只把 MCP 当插件市场，忽略协议带来的权限和上下文边界。
- 工具描述含糊，模型不知道何时调用。
- 给模型暴露过大的文件或数据源，导致上下文噪声和安全风险。
