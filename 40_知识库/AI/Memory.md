# Memory

**定义**: Memory（记忆）是 AI Agent 保存和检索信息的能力，使 Agent 能够记住用户偏好、对话历史、重要事实等，实现跨会话的上下文连续性。

## 记忆的层次

### 1. 短期记忆（Short-term Memory）
- **范围**: 当前对话会话
- **内容**: 最近的对话轮次、当前任务上下文
- **存储**: 内存中，会话结束即清除
- **作用**: 维持当前对话的连贯性

### 2. 长期记忆（Long-term Memory）
- **范围**: 跨所有会话
- **内容**: 用户偏好、重要事实、历史任务结果
- **存储**: 持久化存储（文件/数据库）
- **作用**: 个性化体验，越用越懂你

### 3. 工作记忆（Working Memory）
- **范围**: 当前任务执行过程中
- **内容**: 任务相关的临时数据、中间结果
- **存储**: 内存中
- **作用**: 支持复杂多步骤任务

## 记忆的类型

| 类型 | 描述 | 示例 |
|------|------|------|
| **事实记忆** | 用户的静态信息 | 姓名、职业、时区 |
| **偏好记忆** | 用户的喜好和习惯 | 喜欢简洁回复、工作时间 |
| **情景记忆** | 具体事件的经历 | 上周的项目讨论 |
| **程序记忆** | 如何做事的知识 | 用户的常用工作流 |

## OpenClaw 的记忆系统

### 记忆文件结构

```
~/.openclaw/memory/
├── long-term.json      # 长期记忆
├── short-term.json     # 短期记忆（会话级）
├── preferences.json    # 用户偏好
└── embeddings/         # 向量记忆（用于语义搜索）
```

### 记忆操作

```bash
# 查看记忆
cat ~/.openclaw/memory/long-term.json

# 在对话中让 Agent 记住
"记住我的工作时间是周一到周五 9:00-18:00"

# 询问 Agent 记得什么
"你记得我的哪些信息？"
```

### 记忆示例

```json
{
  "user_preferences": {
    "name": "张三",
    "timezone": "Asia/Shanghai",
    "work_hours": "09:00-18:00",
    "communication_style": "concise"

  "facts": {
    "occupation": "软件工程师",

```

## 记忆的设计挑战

### 1. 记忆过载
- **问题**: 存储过多无关信息，干扰决策
- **解决**: 重要性评分、自动遗忘机制

### 2. 记忆冲突
- **问题**: 用户偏好随时间变化
- **解决**: 时间戳、版本控制、冲突解决策略

### 3. 隐私安全
- **问题**: 敏感信息存储
- **解决**: 加密存储、本地优先、用户控制

### 4. 检索效率
- **问题**: 大量记忆中快速找到相关信息
- **解决**: 向量嵌入、语义搜索、层次索引

## 实践检查清单

- 记忆是否区分事实、偏好、任务和历史对话。
- 是否有写入条件，避免把临时噪音写成长久记忆。
- 是否能解释某条记忆的来源、时间和置信度。
- 是否支持用户查看、修改和删除记忆。
- 检索记忆时是否结合当前任务，而不是无差别注入上下文。

## 案例

个人助理可以长期记住用户偏好的语言、常用工作目录和固定汇报格式，但不应永久保存一次性验证码、临时草稿或未经确认的推测。高质量 Memory 需要“可用、可控、可遗忘”三者同时成立。
