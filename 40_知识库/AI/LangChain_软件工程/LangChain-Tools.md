# LangChain-Tools
LangChain-Tools 是让 Agent 调用外部函数、API、数据库或搜索服务的工具抽象。

## 相关概念
- [[Tool]]
- [[LangChain-Agents]]

## 设计流程

```mermaid
flowchart LR
  A[明确工具职责] --> B[定义参数 schema]
  B --> C[实现外部调用]
  C --> D[返回结构化结果]
  D --> E[记录审计和错误]
```

## 实践检查清单

- 工具名称和描述是否能让模型准确判断何时调用。
- 参数是否有类型、枚举、范围和必填约束。
- 工具是否幂等，或对写操作增加确认和权限检查。
- 错误返回是否可被模型理解并用于下一步决策。
- 是否记录工具输入、输出摘要、耗时和调用结果。

## 案例

查询订单工具应只接收 `order_id` 或明确的过滤条件，并返回订单状态、金额、用户和时间等结构化字段。不要让模型传任意 SQL。

## 设计边界

工具越强，越需要权限和审计。只读工具可以相对开放，写操作、删除操作、支付操作和生产变更应增加确认、审批或沙箱。工具描述要告诉模型何时用、需要什么参数、失败时意味着什么。

返回结果应尽量结构化，并限制大小。大段日志、整页 HTML 或未裁剪的数据库结果会增加上下文噪声，也会让模型难以稳定决策。

工具上线前应准备误调用样例，验证模型是否会在错误场景调用高风险工具。高风险工具还应有 dry-run、确认步骤或人工审批。

## 常见误区

- 工具描述太抽象，模型频繁误调用。
- 直接暴露高权限 API，没有最小权限和审计。
- 返回大段非结构化文本，模型难以稳定解析。

## 复盘问题

- 模型误调用工具时，错误来自描述不清、参数太宽，还是权限边界过大。
- 工具失败后，模型是否能根据错误结构做下一步决策。
