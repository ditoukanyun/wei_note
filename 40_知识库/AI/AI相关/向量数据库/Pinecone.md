# Pinecone
Pinecone 是托管向量数据库服务，常用于生产级语义检索和 RAG 应用。

## 相关概念
- [[向量数据库]]
- [[Embedding]]

## 使用流程

```mermaid
flowchart LR
  A[文本切分] --> B[生成 Embedding]
  B --> C[写入 Pinecone 索引]
  C --> D[向量相似度检索]
  D --> E[返回候选文档]
  E --> F[交给 RAG 生成答案]
```

## 实践检查清单

- 索引维度是否和 Embedding 模型输出一致。
- metadata 是否包含来源、权限、时间和文档类型，便于过滤。
- 命名空间是否按租户、环境或业务隔离。
- 是否评估召回质量、延迟、成本和更新频率。
- 删除文档时是否同步删除向量，避免过期知识被召回。

## 案例

企业知识库 RAG 可以把每个部门文档写入不同 namespace，检索时根据用户所属部门过滤 metadata，避免模型引用用户无权访问的内容。

## 使用边界

Pinecone 适合希望减少自建运维成本的生产检索场景，但托管服务也需要治理。索引维度、相似度指标、namespace、metadata schema 和删除策略一旦确定，就会影响后续迁移和成本。多环境使用时要避免开发数据、测试数据和生产数据混在同一个命名空间。

成本评估不能只看写入量，还要看查询 QPS、索引规模、保留周期和重建频率。RAG 质量差时，也不要只换数据库，切块、Embedding、重排和提示词同样可能是瓶颈。

上线前应准备一组真实查询评估召回质量，并记录索引配置和数据版本。这样后续调参或迁移时才有对比基线。

## 常见误区

- 只看向量相似度，不做权限过滤和来源追踪。
- 文档更新后只新增向量，不删除旧版本。
- chunk 太大导致召回噪声高，太小又丢失上下文。
