# StateGraph
StateGraph 是 LangGraph 中用于定义有状态工作流图的核心抽象，节点共享并更新图状态。

## 相关概念
- [[LangGraph]]
- [[Plan-and-Execute]]

## 建模流程

```mermaid
flowchart LR
  A[定义 State] --> B[添加节点]
  B --> C[添加边和条件边]
  C --> D[编译图]
  D --> E[按输入执行]
```

## 实践检查清单

- State 字段是否清晰表达工作流需要共享的信息。
- 节点是否单一职责，方便测试和复用。
- 条件边是否覆盖成功、失败、重试和结束状态。
- 是否使用 Checkpointer 保存长流程状态。
- 是否记录每个节点输入输出，便于调试 Agent 行为。

## 案例

资料研究 Agent 可以把“检索资料”“提取要点”“生成摘要”“人工确认”建成不同节点，State 中保存资料列表、摘要草稿和确认状态。

## 建模边界

StateGraph 适合状态清晰、步骤可拆、需要条件分支或恢复能力的 Agent 流程。简单线性调用不一定需要图；如果流程开始出现重试、人工确认、工具失败、分支路由和长期运行状态，图结构会比一段顺序代码更容易调试。

State 设计要克制。共享状态过大时，节点会隐式依赖彼此的副作用；共享状态过小时，节点之间又需要重复传参。实践中应把任务目标、关键中间产物、错误状态和人工确认结果放入 State。

调试图工作流时，应优先记录每个节点的输入、输出和状态 diff。这样可以定位是节点逻辑错、条件边错，还是状态被上游污染。

## 常见误区

- 把所有逻辑塞进一个节点，失去图工作流的可观测性。
- State 字段随意增长，节点之间隐式依赖变多。
- 条件边没有失败出口，工具异常后流程卡死。
