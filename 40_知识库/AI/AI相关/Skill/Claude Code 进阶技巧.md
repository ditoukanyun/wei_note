# Claude Code 进阶技巧
Claude Code 进阶技巧包括上下文管理、技能化、计划拆解、测试验证、Git 工作流和自动化协作。

## 相关概念
- [[Claude Code 配置详解]]
- [[Claude Code Skills 开发]]

## 使用流程

```mermaid
flowchart LR
  A[明确任务目标] --> B[收集上下文]
  B --> C[拆解计划]
  C --> D[执行修改]
  D --> E[验证和总结]
```

## 实践检查清单

- 是否先明确目标、约束和验收标准。
- 大任务是否拆成可验证的小批次。
- 是否优先读取现有文件和约定，而不是凭空生成。
- 修改后是否运行对应测试、格式检查或链接校验。
- 是否把重复工作沉淀为 Skill 或脚本。

## 案例

整理知识库时，可以先用脚本找短笔记，再分批补流程图、案例和误区，最后跑 wikilink 校验。这样比随机打开文件补内容更稳定。

## 进阶重点

Claude Code 的进阶能力来自“上下文质量 + 验证闭环”。给出清晰目标、相关文件、约束和验收标准，比要求模型一次性大改更可靠。复杂任务应拆成可检查批次，每批都有 diff、命令输出或文档变更作为证据。

如果某类任务反复出现，例如整理知识库、修测试、生成发布说明，就应该沉淀为脚本或 Skill，减少每次重新解释流程的成本。

进阶使用时还要控制修改范围。一次任务最好有明确文件集合、验证命令和回滚思路，避免模型在不相关区域产生噪声变更。

## 常见误区

- 上来就让模型改大量文件，没有先建立扫描标准。
- 只看最终文本，不验证文件格式和链接完整性。
- 反复做同类任务却不沉淀可复用流程。

## 复盘问题

- 本次任务是否有明确验收命令和修改范围。
- 重复出现的工作是否已经沉淀为脚本、模板或 Skill。
