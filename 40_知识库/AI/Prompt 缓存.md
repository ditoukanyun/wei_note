# Prompt 缓存

## 定义

Prompt 缓存是大模型服务复用相同 Prompt 前缀计算结果的机制。当前缀命中缓存时，系统可以直接加载已有 [[KV Cache]]，减少 [[Prefill 与 Decode|Prefill]] 计算，因此缓存命中 token 通常更便宜。

## 命中条件

- 通常要求 Prompt 前缀完全一致。
- 稳定内容要放在前面，变化内容要放在后面。
- 缓存有有效期，可能从几分钟到几小时不等。
- 供应商对缓存粒度、计费和最小 token 数的规则可能不同。

## 实践方式

- 把系统提示词、工具说明、长文档和固定规范放在 Prompt 开头。
- 把用户问题、时间、随机 ID、短期状态等变化内容放在最后。
- 避免在稳定前缀里插入动态字段，否则后续内容可能全部无法复用。
- 监控缓存命中率和单位任务成本，验证优化是否真实有效。

## 示例

文档问答系统可以把产品手册作为固定前缀，把用户问题追加到最后。只要手册和系统提示词不变，多次请求就更可能命中缓存。
