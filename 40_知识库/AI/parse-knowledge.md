# parse-knowledge
parse-knowledge 是把非结构化材料整理成 OrbitOS 知识库、研究笔记和原子概念的工作流。

## 相关概念
- [[04-领域]]
- [[项目模板]]

## 处理流程

```mermaid
flowchart LR
  A[收集原始材料] --> B[识别主题和领域]
  B --> C[拆分原子概念]
  C --> D[写入知识库或研究笔记]
  D --> E[补 wikilink 和状态]
```

## 实践检查清单

- 原始材料是否保留来源、时间和上下文。
- 是否区分项目行动、研究材料和原子知识点。
- 每个原子概念是否只围绕一个核心问题。
- 是否补充相关概念链接，避免孤立笔记。
- 处理完成后收件箱条目是否标记为已处理。

## 案例

一段关于 RAG 的会议记录可以拆成“检索召回”“重排序”“上下文构建”“评估指标”等原子笔记；待办事项则进入项目或日记，而不是混在知识库正文里。

## 常见误区

- 把整篇文章直接搬进知识库，没有拆分和连接。
- 只整理内容，不记录来源，后续无法复核。
- 把任务、资料和概念混放，导致后续检索困难。
