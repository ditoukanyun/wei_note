# LLM Token 成本

## 定义

LLM Token 成本是调用大模型 API 时按输入、输出、缓存命中等不同 token 类型计费的成本模型。通常输出 token 比输入 token 更贵，因为输出阶段受自回归生成和显存带宽限制，吞吐量远低于输入预填充阶段。

## 成本结构

- 输入 token：主要发生在 [[Prefill 与 Decode|Prefill]] 阶段，可以并行处理，单位成本相对低。
- 输出 token：发生在 [[Prefill 与 Decode|Decode]] 阶段，需要逐 token 串行生成，单位成本相对高。
- 缓存命中 token：命中 [[Prompt 缓存]] 后可以复用 [[KV Cache]]，跳过部分预填充计算，价格通常更低。

## 优化原则

- 把稳定不变的系统提示词、长文档和公共上下文放在 Prompt 前缀，提升缓存命中率。
- 控制输出长度，少生成无价值解释，因为输出 token 通常更贵。
- 不要盲目害怕长输入；如果长上下文能换来短而准确的输出，总成本可能更低。
- 谨慎使用长链路推理模式，因为推理过程可能计入输出 token。
- 对高频调用场景记录输入、输出、缓存命中率和单位任务成本，而不只看总 token 数。

## 示例

客服问答场景中，固定的产品手册和回复规范可以作为稳定前缀，用户问题放在最后。这样同一批请求更容易命中缓存，同时把模型输出限制为直接答案和必要引用，降低输出成本。
