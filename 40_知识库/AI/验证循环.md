# 验证循环

## 定义

验证循环是在 Agent 产出后，用可重复的检查机制判断结果是否满足目标，并把失败信息反馈回 [[编排循环]] 的质量保障机制。它是区分演示型 Agent 和生产级 Agent 的关键。

## 常见验证方式

- 规则验证：单元测试、类型检查、lint、格式校验、schema 校验。
- 运行验证：实际执行命令、跑集成测试、检查退出码和日志。
- 视觉验证：通过截图或浏览器自动化检查 UI 是否符合预期。
- 模型裁判：让另一个模型或子智能体按标准评估输出质量。
- 人工确认：对高风险、合规、安全、产品体验类问题保留人类判断。

## 设计原则

- 优先使用确定性验证，再补充模型裁判。
- 验证失败要返回具体、可行动的错误信息。
- 连续失败需要停止或升级给人，不应无限重试。
- 验证覆盖的是目标达成、质量、安全和副作用，而不只是“代码能跑”。

## 示例

前端 Agent 修改页面后，不应只汇报“已完成”。更好的流程是运行测试、启动本地服务、用浏览器截图检查布局，再把失败信息反馈给模型修复。
