# Gateway
Gateway 是请求入口层，负责路由、鉴权、限流、协议转换和统一治理。

## 相关概念
- [[Spring Cloud Gateway]]
- [[API]]

## 请求流程

```mermaid
flowchart LR
  A[客户端请求] --> B[Gateway]
  B --> C[鉴权和限流]
  C --> D[路由到后端服务]
  D --> E[聚合响应或透传]
```

## 常见职责

- 路由：根据路径、域名、Header 或租户分发请求。
- 安全：统一认证、签名校验和黑白名单。
- 治理：限流、熔断、灰度、降级和观测。
- 协议适配：对外 HTTP，对内 RPC 或其他协议。

## 实践检查清单

- 是否把通用治理放在网关，把业务规则留在服务内。
- 网关超时是否小于下游总超时预算。
- 是否记录请求 ID、上游、下游、耗时和状态码。
- 灰度规则是否可回滚，且不会破坏会话一致性。

## 治理边界

Gateway 应承担横切治理，而不是替代业务服务。认证、限流、路由、灰度、协议适配和基础观测适合放在网关；订单状态、库存规则、价格计算这类业务决策应留在对应服务中。边界清楚时，网关变化不会频繁牵动业务规则。

网关也是高风险入口层，需要高可用、容量压测和降级策略。它一旦失败，影响范围通常大于单个业务服务。

网关变更应配合灰度和回滚。路由、鉴权、限流和 Header 改写都可能影响大量接口，不能只按单服务变更处理。

## 常见误区

- 把大量业务逻辑塞进网关，导致入口层臃肿。
- 网关单点故障，没有高可用和容量规划。
- 只做路由，不做可观测和限流，故障时难以定位。

## 复盘问题

- 当前逻辑属于通用入口治理，还是应下沉到具体业务服务。
- 网关配置变更是否能灰度、回滚并被审计。
- 一旦网关不可用，是否有容量预案、告警和降级入口。
