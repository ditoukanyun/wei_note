# docker-redis集群

docker-redis集群是用 Docker 或 Compose 启动多个 Redis 节点，模拟主从、哨兵或 Cluster 的本地实验环境。

## 要点

- 本地学习可用容器快速搭建多节点。
- 生产 Redis 集群要关注持久化、网络、内存和故障转移。
- 客户端需要支持对应的集群或哨兵模式。

## 相关概念

- [[Redis]]
- [[Docker]]
- [[docker-compose]]

## 常见拓扑

- 主从复制：读扩展和基础容灾，主节点故障需要配合哨兵或人工切换。
- Sentinel：监控主从状态，自动选主，客户端需要支持哨兵发现。
- Cluster：分片存储数据，按槽位分布到多个主节点，适合更大容量和吞吐。

## 实践检查清单

- 每个节点是否使用独立端口、卷和配置文件。
- 本地实验是否固定容器名和网络，便于客户端连接。
- 是否验证故障转移后客户端能重新发现主节点。
- 是否区分普通单机客户端、Sentinel 客户端和 Cluster 客户端。
- 是否理解本地容器集群不能直接代表生产高可用能力。

## 实验重点

本地 Docker Redis 集群最适合用来理解拓扑、客户端连接方式和故障转移行为。实验时不要只验证“能连上”，还要模拟主节点停止、从节点延迟、容器重启、数据卷丢失和网络断开，观察客户端如何重试、重定向或重新发现节点。

生产环境还要额外关注内存策略、持久化、备份、监控、慢查询和容量规划。Docker Compose 可以帮助学习，但不能替代生产级运维设计。

## 常见误区

- 只启动多个 Redis 容器，却没有配置复制、哨兵或槽位。
- 在 Cluster 模式下使用不支持重定向的客户端。
- 忽略持久化配置，容器重建后数据全部丢失。
