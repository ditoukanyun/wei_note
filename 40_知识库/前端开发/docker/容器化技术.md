# 容器化技术

容器化技术把应用及其依赖封装到隔离运行环境中，提升本地开发、测试和部署的一致性。

## 工作流程

```mermaid
flowchart LR
  A[编写 Dockerfile] --> B[构建镜像]
  B --> C[运行容器]
  C --> D[配置网络和卷]
  D --> E[推送镜像并部署]
```

## 实践检查清单

- 镜像是否固定基础版本并尽量精简。
- 配置、密钥和数据是否与镜像分离。
- 容器是否具备健康检查和日志输出。
- 本地、测试、生产是否使用一致的启动方式。
- 是否明确有状态服务的数据卷和备份策略。

## 案例

前端应用可以先用 Node 镜像构建静态产物，再复制到 Nginx 镜像中运行。最终运行镜像只包含静态资源和 Nginx，体积更小、攻击面更低。

## 工程边界

容器化解决环境一致性，但不自动解决部署可靠性。镜像要可重复构建，配置要外部化，日志要输出到标准输出，进程要能响应停止信号，健康检查要能反映服务是否可用。有状态数据应放在卷、数据库或对象存储中，而不是依赖容器文件系统。

容器镜像还要关注供应链风险。基础镜像版本、依赖漏洞、构建缓存、镜像仓库权限和密钥泄露都会影响生产安全。越接近生产，越需要扫描、签名和发布流程约束。

判断容器化是否扎实，可以看新环境能否从源码、配置和镜像仓库完整重建，而不是依赖某台机器上的手工状态。

对于前端项目，还要区分构建时环境变量和运行时配置，避免重新构建镜像才能切换部署环境。

## 常见误区

- 把容器当虚拟机，在容器内手工安装和修改。
- 把密钥写进镜像，推送后难以收回。
- 没有理解数据卷，重建容器时丢失数据。
