# 前端监控与错误上报

## 定义

前端监控与错误上报是采集浏览器端错误、性能指标、资源加载失败、接口异常和用户行为上下文的工程体系。

## 要点

- 错误类型包括 JS 运行时错误、Promise 未处理拒绝、资源加载失败和接口错误。
- 性能指标包括 Web Vitals、页面加载阶段、长任务和自定义业务耗时。
- 上报数据需要采样、脱敏、聚合和告警。

## 采集流程

```mermaid
flowchart LR
  A[浏览器事件] --> B[SDK 捕获]
  B --> C[脱敏和采样]
  C --> D[批量上报]
  D --> E[聚合分析]
  E --> F[告警和复盘]
```

## 实践检查清单

- 是否采集 JS 错误、Promise 错误、资源错误和接口错误。
- 是否记录页面 URL、版本号、用户环境、TraceId 和关键操作路径。
- 是否对手机号、邮箱、Token、请求体等敏感信息脱敏。
- 是否按版本、浏览器、地区和页面聚合错误趋势。
- 是否把前端请求和后端链路追踪通过请求 ID 关联。

## 案例

新版本发布后，某页面白屏率上升。通过监控按版本聚合发现只影响 Safari，错误堆栈指向不兼容的 API，再结合 source map 定位到具体代码行。

## 治理边界

前端监控的目标不是收集越多越好，而是让问题能被发现、定位、分级和复盘。上报字段要覆盖版本、页面、用户环境、操作路径、请求 ID 和错误上下文，同时控制采样率与敏感信息脱敏。数据太少无法定位，数据太多会增加成本和隐私风险。

监控还要和发布流程连接。每次发布应能按版本观察错误率、白屏率和核心性能指标；出现异常时可以快速回滚、关闭开关或定位到具体提交。

## 常见误区

- 只上报错误文本，不带版本和用户环境，导致无法定位范围。
- source map 公开暴露，泄露源码细节。
- 告警阈值没有按流量分层，小页面错误被忽略，大页面偶发错误又频繁报警。

## 掘金文章补充

掘金 RUM SDK 文章提供了一个可落地的 SDK 形态：默认开启错误、网络、性能、路由四件套，其余如 console、resource、behavior、lifecycle、WebSocket、exposure 按需启用。传输层可以按 `sendBeacon -> fetch keepalive -> Image` 降级，发送失败后进入本地离线队列，下次加载再回放。

监控 SDK 的关键不是“尽可能多采”，而是可控采样、可控脱敏和可调插件。字段要做域名/参数白名单、截断、错误去重、行为采样；React 可用 ErrorBoundary/HOC/Hook 捕获组件错误，Vue 可接入全局错误钩子。这样可以在成本、隐私和定位能力之间保持平衡。
