# Web Vitals 与前端性能监控总览

## 学习目标

- 理解 Core Web Vitals 指标与用户体验之间的关系。
- 掌握加载性能、渲染性能、交互性能和稳定性的常见优化方向。
- 能设计基础前端性能监控和错误上报方案。

## 核心概念

- **LCP**：最大内容绘制，衡量主要内容加载速度。
- **INP**：交互到下一次绘制，衡量页面对用户操作的响应能力。
- **CLS**：累计布局偏移，衡量视觉稳定性。
- **资源优化**：压缩、缓存、懒加载、预加载、代码分割。
- **监控闭环**：采集指标、上报数据、聚合分析、定位问题、验证优化效果。

## 推荐阅读顺序

1. [[浏览器]]：理解渲染流程和网络加载。
2. [[Webpack]] 或 [[Vite 原理与插件机制总览]]：理解构建产物优化。
3. 本文：建立性能指标与监控总览。
4. 后续拆分文章：Web Vitals、加载优化、React 性能、错误上报。

## 工程实践清单

- 先用真实用户监控确认瓶颈，再做优化。
- LCP 优化优先关注首屏资源、服务端响应、图片和字体加载。
- INP 优化优先关注长任务、事件回调和不必要的重渲染。
- CLS 优化优先为图片、广告、异步内容预留尺寸。

## 监控闭环

```mermaid
flowchart LR
    A["浏览器采集 Web Vitals"] --> B["前端上报"]
    B --> C["日志/指标平台"]
    C --> D["按页面、设备、地区聚合"]
    D --> E["定位瓶颈"]
    E --> F["优化发布"]
    F --> G["对比优化前后指标"]
```

前端性能优化不能只靠实验室 Lighthouse 分数。真实用户设备、网络、地区和浏览器差异很大，核心指标要进入线上监控。

## 案例

电商首页 LCP 偏高，排查路径可以是：

1. 按页面和设备聚合 LCP，确认移动端更差。
2. 查看 LCP 元素，发现是首屏大图。
3. 优化图片尺寸、格式、缓存和预加载。
4. 发布后对比 P75 LCP 是否下降。

如果只压缩所有资源而不定位 LCP 元素，可能花很多时间却没有改善用户感知。

## 检查清单

- 是否采集 LCP、INP、CLS，并按 P75 看趋势。
- 是否记录页面路由、设备类型、网络类型和版本号。
- 错误上报是否能关联性能指标和发布版本。
- 是否区分实验室测试和真实用户监控。
- 优化后是否有指标对比，而不是只凭主观感觉。
