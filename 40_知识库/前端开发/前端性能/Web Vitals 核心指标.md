# Web Vitals 核心指标

## 定义

Web Vitals 是衡量真实用户体验的一组性能指标，核心关注加载速度、交互响应和视觉稳定性。

## 核心指标

- LCP：最大内容绘制，衡量主要内容加载速度。
- INP：交互到下一次绘制，衡量交互响应。
- CLS：累计布局偏移，衡量视觉稳定性。

## 指标关系

```mermaid
flowchart LR
    A["用户打开页面"] --> B["LCP: 主要内容出现"]
    B --> C["用户点击/输入"]
    C --> D["INP: 交互响应"]
    A --> E["CLS: 页面是否稳定"]
```

## 优化方向

| 指标 | 常见问题 | 优先优化 |
|---|---|---|
| LCP | 首屏图大、服务器慢、资源阻塞 | 图片、缓存、预加载、SSR |
| INP | 长任务、重复渲染、事件过重 | 拆分任务、减少渲染、延迟非关键逻辑 |
| CLS | 图片无尺寸、广告插入、字体切换 | 预留尺寸、稳定布局、字体策略 |

## 检查清单

- 是否按 P75 看真实用户数据，而不是只看单次测试。
- 是否记录页面路径、设备、网络和版本。
- 是否找到 LCP 元素，而不是盲目优化所有资源。
- 是否把性能变化和发布版本关联起来。

## 案例

如果一个页面的 P75 LCP 从 2.1 秒变成 4.5 秒，先不要直接重构 React 组件。应先确认 LCP 元素是什么：如果是首屏大图，就优先看图片尺寸、格式、CDN 缓存和预加载；如果是文本块，就看服务端响应、字体加载和渲染阻塞资源。

## 常见误区

- 只看本机 Lighthouse 分数，不看真实用户数据。
- 只看平均值，不看 P75 或长尾设备。
- 把所有性能问题都归因于前端框架，而忽略网络、图片、字体和后端响应。
- 优化后不按版本对比，无法确认改动是否真的有效。
