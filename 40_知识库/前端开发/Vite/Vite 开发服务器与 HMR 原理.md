# Vite 开发服务器与 HMR 原理

## 定义

Vite 开发服务器利用浏览器原生 ESM 按需加载源码，并通过 HMR 在模块变更时只替换受影响模块，避免完整刷新。

## 要点

- 开发环境不先整体打包，而是按请求转换模块。
- HMR 通过模块图定位变更影响范围。
- 框架插件负责保留组件状态并应用热更新。

## HMR 流程

```mermaid
flowchart LR
  A[文件变更] --> B[开发服务器更新模块图]
  B --> C[通过 WebSocket 通知浏览器]
  C --> D[浏览器请求变更模块]
  D --> E[框架运行热替换逻辑]
```

## 实践检查清单

- HMR 失效时先确认文件监听、模块边界和插件转换结果。
- 组件状态能否保留取决于框架插件和导出结构。
- 依赖变更可能需要重启开发服务器。
- 大型项目应关注文件监听数量和依赖预构建耗时。
- 开发环境快不代表生产包一定小，仍需分析构建产物。

## 案例

React 组件修改样式后能热更新并保留表单状态；如果修改模块导出方式导致边界变化，Vite 可能退化为整页刷新。

## 常见误区

- 认为 HMR 总能保留状态。
- 把 dev server 的按需转换性能等同于生产构建性能。
- 插件顺序错误导致 transform 结果不符合预期。
