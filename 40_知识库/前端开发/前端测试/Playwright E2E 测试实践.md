# Playwright E2E 测试实践

## 定义

Playwright 是浏览器端到端测试工具，用真实浏览器验证登录、创建、支付、发布等关键业务路径。

## 要点

- E2E 测试数量应少而关键。
- 测试数据要可控，避免依赖脆弱环境。
- 使用可访问角色定位能同时提升测试稳定性和可访问性。

## 适合覆盖的路径

- 登录、注册、退出等身份链路。
- 创建、编辑、删除等核心业务闭环。
- 支付、发布、审批等高风险操作。
- 跨页面跳转、权限拦截和错误恢复。

## 执行流程

```mermaid
flowchart LR
  A[准备测试账号和数据] --> B[打开真实页面]
  B --> C[按用户路径操作]
  C --> D[断言可见结果]
  D --> E[清理数据或隔离环境]
```

## 实践检查清单

- 定位优先使用角色、文本和 label，少依赖 CSS 结构。
- 每个测试只验证一个关键路径，避免把多个场景串成超长脚本。
- 测试数据可重复创建和清理，避免污染共享环境。
- CI 中保存 trace、截图和视频，失败时能快速复现。
- 对第三方支付、短信、邮件等外部依赖使用测试环境或契约替身。

## 常见误区

- 把 E2E 当作所有测试的主力，导致反馈慢、失败难定位。
- 用固定等待替代明确等待条件。
- 测试只验证按钮点击成功，没有断言后端状态或用户可见结果。
