# Vitest 单元测试入门

## 定义

Vitest 是 Vite 生态的测试框架，适合测试工具函数、Hook、状态逻辑和轻量组件行为。

## 要点

- API 风格接近 Jest。
- 与 Vite 配置和 TypeScript 生态集成较好。
- 单元测试应关注输入输出和可观察行为。

## 相关概念

- [[前端测试体系总览]]
- [[前端测试金字塔]]

## 适合测试什么

- 纯函数：格式化、计算、校验、数据转换。
- Hook：状态变化、异步请求封装、边界条件。
- Store：action、reducer、selector 和派生状态。
- 轻量组件：输入、点击、禁用态和错误提示等可观察行为。

## 测试组织流程

```mermaid
flowchart LR
  A[确定行为] --> B[准备输入]
  B --> C[执行函数或交互]
  C --> D[断言输出]
  D --> E[覆盖边界条件]
```

## 实践检查清单

- 测试名是否描述业务行为，而不是实现细节。
- 是否覆盖正常、异常、空值和权限等边界。
- Mock 是否只隔离外部依赖，避免把被测逻辑也 Mock 掉。
- 异步测试是否等待用户可见结果，而不是固定 sleep。
- 测试文件是否靠近被测模块，便于一起维护。

## 常见误区

- 只追求覆盖率，缺少关键断言。
- 测试组件内部 state 名称，导致重构时大量无意义失败。
- 在单元测试中启动过多真实依赖，使测试变慢且不稳定。
