# 离线优先

## 定义

离线优先是一种应用设计策略，优先保证用户在网络不稳定或离线时仍能读取、编辑或排队提交数据。

## 要点

- 本地持久化保存关键数据和待同步操作。
- 重新联网后需要冲突解决和同步重试。
- 并非所有业务都适合离线优先，强一致交易要谨慎。

## 相关概念

- [[状态持久化]]
- [[Stale-While-Revalidate]]
- [[最终一致性]]

## 同步流程

```mermaid
flowchart LR
  A[本地读取和编辑] --> B[记录待同步操作]
  B --> C[网络恢复]
  C --> D[上传变更]
  D --> E[冲突检测和合并]
```

## 实践检查清单

- 哪些数据可以离线修改，哪些必须在线确认。
- 本地操作是否有队列、顺序和重试策略。
- 冲突解决是自动合并、后写覆盖还是用户选择。
- 是否为用户展示同步中、已同步和失败状态。
- 敏感数据本地持久化是否加密或最小化。

## 案例

笔记应用适合离线优先，用户离线编辑后重新联网同步；如果同一篇笔记在两台设备修改，需要冲突提示或版本合并。

## 常见误区

- 只做本地缓存，不处理重新联网后的冲突。
- 把支付、库存扣减等强一致操作也离线排队。
- 同步失败没有用户反馈，数据看似保存实际丢失。
