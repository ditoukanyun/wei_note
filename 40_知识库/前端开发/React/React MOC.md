## 实践检查清单

- 是否先掌握组件、props、state、effect 和事件处理。
- 状态管理是否从本地状态开始，再评估全局方案。
- 性能优化是否基于 Profiler 证据。
- 项目实践是否包含接口、路由、权限、测试和部署。
- 源码学习是否服务于理解实际问题，而不是孤立背诵。

## 案例

学习 React 后台项目时，可以先做列表和表单，再加入路由、请求封装、权限守卫、测试和构建部署，最后再深入并发特性和源码调度。

## 使用方式

MOC 的作用是导航，不是替代原子笔记。复习时可以先从 MOC 进入主题，找到当前问题相关的概念，再跳转到具体笔记。学习路径也应从项目问题倒推知识点：表单复杂就补状态边界，列表卡顿就补渲染优化，接口不稳定就补请求和错误处理。

维护 React MOC 时，应定期检查新增笔记是否已经连接进路径。没有入口的笔记很容易被遗忘，入口过多又会让导航失去重点。

## 常见误区

- 一开始就学习源码，缺少真实项目问题支撑。
- 状态管理工具学很多，但组件边界仍然混乱。
- 只做页面样式，不处理异常态和测试。

## 复盘问题

- 当前 React 学习是否有项目场景承接。
- 新增 React 笔记是否已经连接到 MOC 和相关实践主题。
