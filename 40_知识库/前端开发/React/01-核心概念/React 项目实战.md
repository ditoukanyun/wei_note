# React 项目实战

React 项目实战是把组件、状态、路由、请求、权限、测试、构建和部署组合为完整应用的练习。

## 实战路径

```mermaid
flowchart LR
  A[搭建项目] --> B[设计路由和布局]
  B --> C[封装请求和状态]
  C --> D[实现业务页面]
  D --> E[测试、构建和部署]
```

## 实践检查清单

- 是否有清晰的目录结构和模块边界。
- 请求层是否统一处理认证、错误、超时和取消。
- 组件是否按页面、业务组件和基础组件拆分。
- 是否覆盖登录、权限、空态、错误态和加载态。
- 构建产物是否能在目标部署环境正确运行。

## 案例

做一个后台管理项目时，先实现登录、路由守卫、列表查询、表单编辑和错误处理，再补测试和部署。不要一开始就沉迷复杂组件库封装。

## 拆解方法

React 项目实战可以按“页面骨架、数据流、交互状态、异常状态、交付验证”拆解。页面骨架负责路由和布局；数据流负责接口、缓存和表单提交；交互状态覆盖加载、禁用、确认和撤销；异常状态覆盖无权限、空数据、接口失败和会话过期；交付验证则包含单元测试、E2E、构建产物和部署环境。

评估一个项目是否扎实时，不只看页面数量，而要看关键业务路径能否从用户入口走到数据落库，并且失败时有可理解的反馈。

项目复盘时可以用“新增一个业务页面需要改哪些地方”来检查架构。如果每次都要同时改路由、权限、请求、类型、状态、测试和菜单，并且没有固定模板，说明项目工程化还不够稳定。

## 常见误区

- 只做页面静态效果，忽略接口契约和异常状态。
- 状态管理过早全局化，导致简单页面也难维护。
- 没有端到端验证，部署后才发现路由或环境变量问题。
