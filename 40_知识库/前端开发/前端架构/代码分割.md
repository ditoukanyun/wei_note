# 代码分割

## 定义

代码分割是把应用产物拆成多个按需加载的 chunk，减少首屏 JavaScript 体积并改善加载性能。

## 要点

- 路由级分割适合大型单页应用。
- 组件级懒加载适合低频重型模块。
- 分割过细会增加请求和调度成本。
- 需要配合缓存策略和加载状态设计。

## 加载流程

```mermaid
flowchart LR
    A["用户访问首页"] --> B["加载主 bundle"]
    B --> C["渲染基础框架"]
    C --> D["进入某个路由"]
    D --> E["按需加载路由 chunk"]
    E --> F["展示页面内容"]
```

代码分割的目标是让用户先拿到当前页面必需代码，把低频页面、重型组件和管理后台模块延后加载。

## 常见分割粒度

- **路由级分割**：最常见，适合 SPA 的页面维度拆分。
- **组件级分割**：适合富文本编辑器、图表、地图、上传器等重型低频组件。
- **依赖级分割**：把 React、图表库、编辑器等第三方依赖拆成可缓存 chunk。
- **业务域分割**：大型后台按订单、用户、财务等模块分割。

## 示例

```tsx
import { lazy, Suspense } from "react";

const OrderPage = lazy(() => import("./pages/OrderPage"));

export function App() {
  return (
    <Suspense fallback={<span>加载中...</span>}>
      <OrderPage />
    </Suspense>
  );
}
```

这个写法会让构建工具把 `OrderPage` 拆成独立 chunk，只有真正渲染到该页面时才下载。

## 检查清单

- 首屏是否只加载当前路径必需代码。
- 加载状态是否稳定，避免空白屏和布局跳动。
- 分割粒度是否合理，避免过多小 chunk 造成请求调度成本。
- 产物文件名是否带内容哈希，支持长期缓存。
- 是否用构建分析工具定位最大的模块。
- 是否结合 [[React 性能优化]] 和 [[Web Vitals 核心指标]] 验证收益。
