# HTTP/HTTPS
HTTP 是 Web 通信协议，HTTPS 在 HTTP 之上加入 TLS 加密和身份校验。

## 相关概念
- [[RESTful API 设计]]
- [[SSL/TLS]]

## 请求响应流程

```mermaid
flowchart LR
  A[客户端构造请求] --> B[DNS 和连接建立]
  B --> C[发送 HTTP 请求]
  C --> D[服务端处理]
  D --> E[返回状态码、Header、Body]
  E --> F[客户端解析和缓存]
```

## 实践检查清单

- 方法语义是否正确：GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除。
- 状态码是否表达真实结果，例如 400、401、403、404、409、500。
- Header 是否正确处理认证、缓存、内容类型和跨域。
- HTTPS 是否覆盖登录、支付、后台和所有敏感接口。
- 是否有超时、重试、幂等和请求追踪 ID。

## 案例

表单重复提交时，如果创建接口没有幂等键，用户刷新或网络重试可能创建多条记录。HTTP 层应结合业务唯一键、幂等键或 409 冲突语义处理重复请求。

## 常见误区

- 所有错误都返回 200，再用业务码表达失败，增加客户端和监控复杂度。
- GET 接口产生副作用，容易被缓存、预取或爬虫误触发。
- 只配置 HTTPS 首页，接口仍走明文 HTTP。
