# 数据加密
数据加密通过算法保护传输或存储中的敏感数据，常见场景包括 HTTPS、密码哈希和字段加密。

## 相关概念
- [[SSL/TLS]]
- [[API 安全基础]]

## 常见类型

- 传输加密：用 TLS 保护网络传输过程。
- 存储加密：数据库、磁盘或对象存储中的敏感数据加密。
- 密码哈希：密码不应可逆加密，而应使用带盐的慢哈希。
- 字段加密：对身份证、银行卡等敏感字段单独加密和脱敏展示。

## 处理流程

```mermaid
flowchart LR
  A[识别敏感数据] --> B[选择加密或哈希方式]
  B --> C[管理密钥和盐]
  C --> D[最小化解密入口]
  D --> E[审计访问记录]
```

## 实践检查清单

- 密钥是否由专门系统或环境变量管理，避免写入代码仓库。
- 是否区分可逆加密和不可逆哈希。
- 加密前后是否仍满足查询、排序和脱敏展示需求。
- 解密操作是否有权限控制和审计。
- 是否设计密钥轮换和历史数据重加密策略。

## 设计边界

加密不是单点功能，而是数据生命周期治理。要先识别数据在采集、传输、存储、使用、展示、备份和删除阶段分别面临什么风险。传输层用 TLS，密码用慢哈希，敏感字段按需加密和脱敏，密钥则应和密文分离管理。

加密会影响查询和运维。加密字段通常不适合模糊查询和排序，密钥轮换也需要历史数据迁移方案。若没有解密审计，拥有密钥的人就可能绕过业务权限读取敏感信息。

落地时还要定义脱敏展示规则。很多场景并不需要解密完整数据，只需要展示后四位、局部掩码或校验结果，能不解密就不解密。

加密方案上线前应做一次恢复演练，确认密钥丢失、轮换失败或历史数据迁移时有可执行预案。

## 常见误区

- 自己设计加密算法，而不是使用成熟标准库。
- 把密钥和密文放在同一个数据库或配置文件中。
- 用普通哈希存密码，没有盐和慢哈希。
