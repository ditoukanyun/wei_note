# API 测试
API 测试通过请求、断言和环境配置验证接口行为、错误码、认证和兼容性。

## 相关概念
- [[RESTful API 设计]]
- [[OpenAPI]]

## 测试流程

```mermaid
flowchart LR
  A[阅读接口契约] --> B[准备环境和认证]
  B --> C[构造请求数据]
  C --> D[断言状态码和响应体]
  D --> E[覆盖异常和兼容性]
```

## 实践检查清单

- 是否覆盖正常输入、缺失字段、非法字段和边界值。
- 是否验证状态码、错误码、响应结构和关键业务字段。
- 是否测试认证、授权、幂等、分页、排序和过滤。
- 是否区分测试环境数据和生产数据。
- 是否把稳定用例自动化到 CI，避免只靠手工点接口。

## 案例

创建订单接口除了测试成功创建，还要测试库存不足、重复提交、无权限、价格变化和参数缺失。若接口声明幂等键，必须验证同一幂等键重复请求不会创建多笔订单。

## 测试边界

API 测试应围绕契约和业务语义，而不是只确认接口能调通。一个接口至少要覆盖成功路径、参数错误、权限错误、资源不存在、状态冲突和幂等行为。对外接口还要关注兼容性：新增字段通常安全，删除字段或改变含义则可能破坏调用方。

自动化 API 测试要保证数据可重复。测试前准备数据，测试后清理或使用隔离环境，避免用残留脏数据制造偶发失败。

对核心接口，应把接口文档、自动化用例和真实错误样例关联起来。这样接口变更时可以同步更新契约和回归测试，而不是靠人工记忆。

## 常见误区

- 只测试 200 响应，不测试失败语义。
- 用同一条脏数据反复测试，导致结果不可重复。
- 接口变更后不更新契约和自动化用例。

## 复盘问题

- 这个接口的失败场景是否和成功场景一样被自动化覆盖。
- 测试数据是否能重复创建、隔离和清理。
