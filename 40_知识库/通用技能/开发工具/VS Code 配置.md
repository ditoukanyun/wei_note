# VS Code 配置
VS Code 配置包括扩展、快捷键、格式化、调试、工作区设置和语言服务器。

## 配置层级

- 用户设置：影响当前用户所有项目。
- 工作区设置：只影响当前项目，适合团队共享。
- 语言设置：按文件类型覆盖格式化、缩进和工具链。
- 扩展配置：由插件提供，如 ESLint、Prettier、Python、Java。

## 配置流程

```mermaid
flowchart TD
    A["确认项目技术栈"] --> B["安装必要扩展"]
    B --> C["配置格式化和 Lint"]
    C --> D["设置调试和任务"]
    D --> E["沉淀工作区配置"]
```

## 实践检查清单

- 是否区分个人偏好和团队共享配置。
- 格式化工具是否唯一，避免 Prettier 和语言服务冲突。
- 是否配置保存时格式化、Lint 修复和导入整理。
- 是否有可复用的 debug 配置和 tasks。
- 新成员是否能通过工作区配置快速进入开发。

## 案例

前端项目可以在 `.vscode/settings.json` 中指定默认格式化器为 Prettier，开启 ESLint 保存修复，并在 `extensions.json` 推荐团队必装插件。这样能减少“我这里格式不一样”的协作成本。

## 团队协作边界

适合提交到仓库的是能提高一致性的工作区配置，例如推荐扩展、调试入口、测试任务、默认格式化器和项目特定的语言设置。个人主题、字体、缩放、光标样式和私人快捷键应留在用户设置里，避免污染团队体验。

配置要和项目工具链保持一致。若项目已经用 ESLint 和 Prettier 管理格式，就不要再让多个扩展同时修改同一段代码。调试配置也应尽量使用项目脚本和环境变量，减少“只在某个人电脑可用”的隐式依赖。

## 常见误区

- 把个人主题、字体、快捷键提交到团队配置。
- 多个格式化器同时生效，导致保存后代码来回变化。
