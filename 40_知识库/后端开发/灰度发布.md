# 灰度发布

## 定义

灰度发布是一种逐步开放新版本或新功能的发布策略，通过小范围用户、白名单、百分比分桶或特定条件逐步放量，降低一次性全量发布的风险。

## 解决的问题

- 新版本风险未知，不适合一次性开放给全部用户。
- 需要在真实流量中验证错误率、性能和业务指标。
- 出现问题时希望快速停止放量或回退到旧路径。

## 要点

- 先让小范围用户命中新功能，再逐步扩大比例。
- 需要监控错误率、性能指标和业务指标，发现问题及时回滚或降级。
- 百分比灰度应使用[[稳定哈希]]，保证同一用户命中结果稳定。
- 常与[[Feature Flag]]、网关路由、API 版本管理配合使用。
- 灰度规则要可解释，方便定位某个用户为什么命中新版本。
- 放量节奏应与风险等级匹配，而不是机械按比例提升。

## 示例

新结账流程先对白名单用户开放，再将 `rolloutPercent` 调整到 30%，符合分桶条件的用户进入新版路径，其余用户仍走旧版路径。

对应模块：[[SpringBoot/35-SpringBoot-FeatureFlag与灰度发布]]、[[SpringBoot/22-SpringBoot-API版本管理]]。

## 常见方式

| 方式 | 说明 |
|---|---|
| 白名单灰度 | 先给内部用户、测试租户或特定客户开放 |
| 百分比灰度 | 用稳定分桶逐步扩大流量比例 |
| 区域灰度 | 按地区、机房、渠道或客户端版本开放 |
| 网关灰度 | 在入口层按 header、cookie、用户 ID 或路径路由 |

## 易错点

- 只做流量切分，没有配套监控和回滚策略。
- 灰度分桶不稳定，用户在新旧版本之间来回跳。
- 新旧版本共享数据结构不兼容，回滚后旧版本无法读取新数据。
