# CQRS

## 定义

CQRS（Command Query Responsibility Segregation）是一种将写入命令模型与读取查询模型分离的架构模式。命令侧处理业务变更和一致性约束，查询侧维护面向展示、检索或报表优化的读模型。

## 解决的问题

- 同一个模型同时承担复杂写入规则和高性能查询，导致模型臃肿。
- 查询形态与领域模型差异大，直接查询写模型成本高。
- 读写负载差异明显，需要分别扩展和优化。

## 要点

- Command 负责改变状态，例如创建订单、支付订单、取消订单。
- Query 只负责读取数据，不承担业务写入。
- 写模型可以产生[[领域事件]]，由投影器生成读模型。
- 读模型通常是可重建的，可以从事件或业务表重新投影。
- CQRS 常引入[[最终一致性]]：读模型可能短暂落后于写模型。
- CQRS 不等于必须使用[[Event Sourcing]]；它可以基于普通关系表、消息或事件流实现。

## 示例

订单写模型接收 `CreateOrder`、`PayOrder` 等命令并产生 `OrderCreated`、`OrderPaid` 等事件；投影器消费事件生成订单摘要读模型，供列表页和详情页查询。

对应模块：[[SpringBoot/33-SpringBoot-CQRS读模型]]。

## 适用场景

- 读多写少，查询模型与写模型差异明显。
- 页面需要聚合、反范式化或预计算数据。
- 业务写入规则复杂，需要保持领域模型清晰。

## 易错点

- 在简单 CRUD 系统中过早引入 CQRS，增加同步、投影和排障成本。
- 没有处理投影延迟，导致用户提交后立刻查询看不到数据。
- 读模型被当作事实来源，反向影响写侧业务判断。
