# SQL_常用查询技巧

SQL 常用查询技巧包括 JOIN、聚合、窗口函数、CTE、子查询、分页和执行计划分析。

  A[明确问题] --> B[确定表和关联]

  C --> D[查看执行计划]

## 实践检查清单

- JOIN 条件是否明确，避免笛卡尔积。
- WHERE 条件是否能利用索引。
- 分页是否避免深 offset 带来的扫描成本。
- 聚合和窗口函数是否先缩小数据范围。
- 上线前是否用真实数据量查看执行计划。

## 案例

查询每个用户最近一笔订单，可以用窗口函数按用户分组排序取第一条；旧版本 MySQL 可用子查询或 JOIN 最大时间，但要注意同一时间多条记录的处理。

## 调优边界

SQL 优化应先确认业务问题和数据规模，再看执行计划。小数据下能跑不代表线上可用，尤其是 JOIN、排序、分组和深分页。排查慢查询时可以先看扫描行数、索引命中、临时表、文件排序和回表成本，再决定是补索引、改写查询，还是调整数据模型。

常用技巧也要有边界。窗口函数可读性好，但可能带来排序成本；CTE 能拆解复杂逻辑，但不一定总比子查询更快；分页要根据业务选择 offset、游标或时间线方案。

写复杂 SQL 后应沉淀查询意图和关键假设，例如数据量、索引、排序规则和分页方式。否则后续维护者只能从语句反推业务含义，修改风险会明显变高。

## 常见误区

- 只在少量测试数据上验证 SQL。
- SELECT 取出所有列，增加网络和回表成本。
- 复杂查询不看执行计划，慢了才临时加索引。
