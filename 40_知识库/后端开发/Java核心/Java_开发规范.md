# Java_开发规范

Java 开发规范是团队对命名、分层、异常、日志、事务、测试和代码风格的统一约定。

## 相关概念

- [[SpringBoot]]
- [[API 安全基础]]
- [[可观测性总览：日志、指标与链路追踪]]

## 规范维度

- 命名：类名表达领域对象或能力，方法名表达动作，布尔字段避免双重否定。
- 分层：Controller 只做协议适配，Service 编排业务，Repository 处理数据访问。
- 异常：业务异常可预期、系统异常可观测，不吞异常、不用异常做正常分支。
- 日志：关键业务链路记录上下文、结果和耗时，避免输出密码、Token 和身份证等敏感信息。
- 事务：事务边界放在业务用例层，避免在循环、远程调用和长耗时逻辑里扩大事务。

## 实践检查清单

- 新接口是否有统一响应、错误码和参数校验。
- 新增日志是否能定位请求、用户、资源和失败原因。
- 数据库写操作是否明确事务边界和幂等策略。
- 公共工具类是否有单元测试，避免在业务代码中复制粘贴。

## 常见误区

- 只统一格式，不统一分层、异常和日志语义。
- 把所有逻辑塞进 Service，导致方法过长且难以测试。
- 用全局异常处理掩盖业务边界不清的问题。
