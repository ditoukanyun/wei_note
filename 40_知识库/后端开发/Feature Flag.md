# Feature Flag

## 定义

Feature Flag 是一种通过运行时配置控制功能开关的发布技术，让功能发布与代码部署解耦。系统可以根据全局开关、白名单、用户属性或百分比灰度决定用户是否进入新功能路径。

## 解决的问题

- 代码已经部署，但功能还不希望对所有用户开放。
- 新功能需要逐步验证、快速回滚或仅对特定用户启用。
- 团队希望减少长期分支，把未完全开放的功能合入主干。

## 要点

- 代码可以先部署，功能是否启用由配置决定。
- 常见规则包括全局开关、白名单、百分比灰度和用户分群。
- 百分比灰度需要[[稳定哈希]]，避免同一用户体验抖动。
- 业务响应最好包含命中原因和分桶信息，便于排查。
- 长期不用的 flag 应及时清理，否则会增加代码复杂度。
- Feature Flag 常用于[[灰度发布]]、A/B 测试、权限开关和运维降级。

## 示例

`new-checkout` 开关控制用户进入新版结账还是旧版结账；白名单用户优先命中，新用户可按 30% 灰度比例逐步放量。

对应模块：[[SpringBoot/35-SpringBoot-FeatureFlag与灰度发布]]。

## 常见规则

| 规则 | 说明 |
|---|---|
| 全局开关 | 对所有用户启用或关闭 |
| 白名单 | 指定用户、租户或环境命中新功能 |
| 百分比灰度 | 根据稳定分桶逐步放量 |
| 属性规则 | 根据地区、版本、角色、渠道等条件判断 |

## 易错点

- flag 生命周期无人管理，旧分支长期留在代码里。
- 使用随机数做百分比灰度，导致同一用户反复切换体验。
- 只控制前端展示，不控制后端真实业务路径，造成权限或状态不一致。
