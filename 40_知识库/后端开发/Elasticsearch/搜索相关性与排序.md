# 搜索相关性与排序

## 定义

搜索相关性与排序决定搜索结果如何从“匹配”变成“更符合用户意图的顺序”。它通常结合文本匹配得分、业务权重、时间新鲜度、点击转化和个性化信号。

## 要点

- Elasticsearch 默认使用 BM25 等评分模型衡量文本相关性。
- 精确过滤不等于排序，过滤只决定候选集合。
- 业务排序常结合销量、热度、库存、发布时间和权限。
- 相关性调优需要搜索日志、点击数据和人工评估集。

## 常见手段

- 字段 Boost：标题命中权重大于正文命中。
- Function Score：把业务分数加入排序。
- 同义词和分词优化：提升召回质量。
- 二次排序：先相关性，再时间或业务指标。

## 排序流程

```mermaid
flowchart LR
    A["用户查询"] --> B["分词与召回"]
    B --> C["BM25 相关性评分"]
    C --> D["业务特征加权"]
    D --> E["过滤权限/库存/状态"]
    E --> F["分页与展示"]
    F --> G["点击日志反馈"]
```

搜索排序不是一次配置完成的功能，它需要用真实查询、点击、转化和人工评估持续调优。

## 案例

电商搜索“机械键盘”时，标题命中“机械键盘”的商品应优先于正文或评论命中的商品；但如果某商品无库存，排序应降低或过滤；新品、促销、销量可以作为业务加权信号。

一个简化策略：

- `title` 字段 boost 高于 `description`。
- 有库存商品加权。
- 近期上架商品增加时间新鲜度。
- 点击率和转化率作为离线特征定期更新。

## 检查清单

- 是否区分过滤条件和排序条件。
- 标题、类目、品牌、正文等字段权重是否符合业务。
- 同义词、停用词和分词器是否覆盖高频搜索词。
- 排序调优是否有查询日志和人工评估集。
- 是否监控无结果率、点击率、转化率和搜索延迟。
- 分页深度是否受控，避免深分页拖垮集群。
