# Spring 框架

Spring 框架是 Java 企业应用开发基础框架，核心能力包括 IoC 容器、依赖注入、AOP、事务管理和生态集成。

## 相关概念

- [[SpringBoot]]
- [[Java 反射]]
- [[Spring Security 入门]]

## 核心流程

```mermaid
flowchart LR
  A[扫描 Bean 定义] --> B[创建和依赖注入]
  B --> C[应用 AOP 和代理]
  C --> D[处理事务和生命周期]
  D --> E[对外提供服务]
```

## 实践检查清单

- Bean 职责是否清晰，避免把所有逻辑放进一个 Service。
- 依赖注入是否使用构造器注入，减少隐藏依赖。
- AOP 是否用于横切关注点，而不是替代业务逻辑。
- 事务边界是否放在业务用例层。
- 配置是否区分框架约定和业务自定义。

## 案例

订单服务中，Controller 接收请求，Service 编排下单流程，Repository 访问数据库，事务放在 Service 方法上。日志、鉴权和事务可以通过框架能力处理，但核心业务规则仍应在明确的业务代码中。

## 学习边界

学习 Spring 要把“容器能力”和“业务设计”分开。IoC、AOP、事务和事件发布可以减少样板代码，但它们不会自动让业务边界清晰。Bean 生命周期、代理机制和事务传播是排查问题时必须理解的底层概念。

在项目中应优先保持分层清楚：Controller 做协议适配，Service 表达业务用例，Repository 处理持久化。框架注解只负责连接这些层，不应掩盖混乱的职责分配。

## 常见误区

- 过度依赖注解，忽略背后的 Bean 生命周期和代理机制。
- 在同类内部调用事务方法，以为事务会自动生效。
- 把 Spring 容器当全局变量仓库滥用。
