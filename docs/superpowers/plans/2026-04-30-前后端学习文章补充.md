# TypeScript 工程实践总览

## 学习目标

- 理解 TypeScript 在前端工程中的价值：类型约束、编辑器提示、重构安全和接口协作。
- 掌握项目级配置：`tsconfig.json`、路径别名、类型声明文件和严格模式。
- 能在 React、Vite、Node 工具脚本中合理使用 TypeScript。

## 核心概念

- **类型系统**：基础类型、联合类型、交叉类型、字面量类型、类型收窄。
- **泛型**：用类型参数表达输入和输出之间的关系。
- **工具类型**：`Partial`、`Pick`、`Omit`、`Record`、`ReturnType`。
- **声明文件**：用 `.d.ts` 补充第三方库或全局变量类型。
- **工程配置**：通过 `strict`、`baseUrl`、`paths`、`types` 控制项目类型检查行为。

## 推荐阅读顺序

1. [[JavaScript]]：先熟悉 JavaScript 运行时语义。
2. [[React 基础]]：理解组件、props、state 后再学习 React 类型写法。
3. 本文：建立 TypeScript 工程全局视角。
4. 后续拆分文章：类型系统、泛型、React 类型实践、tsconfig 配置。

## 工程实践清单

- 新项目优先开启 `strict`，旧项目可以分模块逐步收紧。
- API 响应、表单数据、路由参数和组件 props 应优先定义明确类型。
- 公共类型放在靠近业务的模块中，避免过早建立庞大的全局 types 目录。
- 类型用于表达约束，不要为了炫技写难以维护的类型体操。

# Vite 原理与插件机制总览

## 学习目标

- 理解 Vite 为什么开发环境启动快、热更新快。
- 掌握 Vite 在开发环境和生产构建中的不同工作方式。
- 能阅读和编写基础 Vite 插件，解决项目构建中的定制需求。

## 核心概念

- **原生 ESM**：开发环境直接利用浏览器的 ES Module 能力。
- **依赖预构建**：使用 esbuild 将 CommonJS 或多模块依赖转换为更适合浏览器加载的形式。
- **HMR**：只替换变更模块，保留应用状态并减少刷新成本。
- **生产构建**：生产环境仍基于 Rollup 做打包、分块和优化。
- **插件机制**：Vite 插件沿用 Rollup 插件模型，并增加开发服务器相关钩子。

## 推荐阅读顺序

1. [[模块化]]：理解 ESM、CommonJS 和打包器的背景。
2. [[Webpack]]：对比传统打包器的开发体验。
3. 本文：建立 Vite 原理总览。
4. 后续拆分文章：HMR、依赖预构建、插件开发、构建优化。

## 工程实践清单

- 小型 React/Vue 项目优先使用 Vite 初始化。
- 构建问题先检查插件顺序、路径别名、环境变量和依赖预构建配置。
- 插件开发从 `config`、`transform`、`configureServer` 三类常用钩子开始。
- 生产构建优化关注 chunk 拆分、静态资源缓存和 sourcemap 策略。

## 后续可拆分文章

- [[Vite 开发服务器与 HMR 原理]]
- [[Vite 依赖预构建]]
- [[Vite 插件开发入门]]

# Next.js App Router 总览

## 学习目标

- 理解 App Router 相比 Pages Router 的核心变化。
- 掌握路由、布局、服务端组件、数据获取、缓存和部署的基本模型。
- 能判断页面应该使用 SSR、SSG、ISR 还是客户端渲染。

## 核心概念

- **文件系统路由**：`app` 目录中的文件和文件夹决定路由结构。
- **Layout**：跨页面共享 UI 和状态边界。
- **Server Components**：默认在服务端渲染，减少客户端 JavaScript 体积。
- **Client Components**：通过 `use client` 使用浏览器 API、事件和客户端状态。
- **缓存策略**：数据请求、路由段和页面输出都有独立缓存语义。

## 推荐阅读顺序

1. [[React 基础]]：先理解组件和状态。
2. [[Hooks]]：理解客户端组件中的交互逻辑。
3. 本文：建立 Next.js App Router 总览。
4. 后续拆分文章：路由、RSC、缓存、认证、部署。

## 工程实践清单

- 默认优先使用 Server Components，只有需要交互或浏览器 API 时才使用 Client Components。
- 数据获取尽量靠近使用位置，避免把所有请求集中到页面顶层。
- 认证、缓存和重定向需要结合运行环境设计，不能只按客户端 SPA 思路处理。
- 部署前检查运行时、环境变量、图片优化和缓存失效策略。

- 组件测试关注用户能看到和能操作的行为，而不是内部 state 名称。

# 前端安全总览：XSS、CSRF 与 CSP

## 学习目标

- 理解前端常见安全风险的攻击面和防护思路。
- 掌握 XSS、CSRF、CSP、Token 存储安全的基本实践。
- 能在设计登录态、富文本、第三方脚本和接口请求时主动识别风险。

## 核心概念

- **XSS**：攻击者把恶意脚本注入页面，窃取数据或冒用用户操作。
- **CSRF**：攻击者诱导已登录用户向目标站点发起非预期请求。
- **CSP**：通过响应头限制脚本、样式、图片等资源来源。
- **Token 存储**：在安全性、可用性和跨端需求之间权衡 Cookie、内存、localStorage。
- **输入输出边界**：用户输入、富文本、URL 参数和第三方内容都需要按上下文处理。

## 推荐阅读顺序

1. [[网络]]：理解 Cookie、Header、同源策略和 CORS。
2. [[认证授权总览：Session、JWT、OAuth2 与 OIDC]]：理解登录态设计。
3. 本文：建立前端安全总览。
4. 后续拆分文章：XSS、CSRF、CSP、Token 存储。

## 工程实践清单

- 默认不要把不可信 HTML 直接插入 DOM。
- Cookie 登录态优先考虑 `HttpOnly`、`Secure`、`SameSite`。
- 重要写操作使用 CSRF Token、SameSite Cookie 或双重提交策略。
- 第三方脚本接入前评估权限、加载来源和故障影响。

## 后续可拆分文章

- [[XSS 攻击与防护]]
- [[CSRF 攻击与防护]]
- [[CSP 内容安全策略]]
- [[前端鉴权与 Token 存储安全]]

## 相关链接

- [[前端开发 MOC]]
- [[前端测试体系总览]]

## 工程实践清单

- 内部管理系统优先从 Session 或 JWT + RBAC 开始。
- 第三方登录、开放授权和企业单点登录优先理解 OAuth2/OIDC。
- Token 设计需要同时考虑签发、校验、刷新、撤销和审计。
