# 案例验证记录

验证日期：2026-10-21，北京时间。执行环境为 Apple 芯片 Mac、Docker Desktop，运行容器为 Linux arm64。

## 构建与单元测试

- `docker compose config --quiet`：通过。
- `docker compose up -d --build`：成功构建并启动全部默认服务。
- Java 17 容器内 Maven 构建：通过。
- 7 项 Java 测试：全部通过，失败 0、错误 0、跳过 0。

| 测试 | 验证目标 |
| --- | --- |
| 有效配置替换 | 新快照包含完整新值，旧快照仍保持原值 |
| 非法配置与删除 | 范围越界、类型错误、空配置保留上次有效快照 |
| 重复 YAML 属性 | 拒绝有歧义的配置 |
| 单笔失败后恢复 | 失败保持待补偿；恢复后成功；重复执行不新增流水 |
| 并发处理 | 两个线程同时处理同一订单，只产生一条业务流水 |
| 数据库异常 | 本地业务效果失败时，尝试次数与状态按事务回滚 |
| 分片范围与批量 | 只处理指定区域，单次处理数量受批量配置限制 |

单元测试使用 H2 的 PostgreSQL 兼容模式，事务方法通过实际 Spring 代理调用。真实 PostgreSQL 与框架联动由下面的端到端验证覆盖。

## Docker 端到端验证

执行命令：

```bash
docker compose run --rm verify
```

实际结果：

| 验证步骤 | 实际结果 |
| --- | --- |
| 初始化 | 创建开发与测试命名空间，分别加载 `false / 100`、`false / 7` |
| 关闭开关时触发 | 三个分片有执行记录，业务流水为 0 |
| 发布开发 `true / 20` | 两个开发实例刷新成功，测试实例保持原值 |
| 第一次业务执行 | 两个实例参与三个分片；11 成功、1 待补偿、11 条流水 |
| 恢复模拟依赖后执行 | 12 成功、0 待补偿、12 条流水 |
| 额外再次触发 | 订单与尝试次数不变，流水仍为 12 |
| 测试环境数据库 | 未被开发任务写入，业务流水仍为 0 |
| 发布批量 0 | 两个开发实例拒绝变更，保持之前的有效配置版本 |
| 测试环境单独发布 | 测试实例单独刷新，开发值保持不变 |
| 对比启动标识 | 所有实例在配置变更全过程均未重启 |
| 发布批量 2 | 三个分片首轮共处理 6 笔，第二轮累计完成 12 笔 |
| 验证结束 | 自动恢复开发 `false / 100`、测试 `false / 7` 及 12 笔待补偿订单 |

脚本以退出码 0 完成，输出“全部端到端验证通过，已恢复演示起始状态”。完整输出见同目录的《端到端验证输出.txt》。

## 运行中确认的版本细节

- ElasticJob 3.0.4 的显式时区参数需要 GMT 格式；代码采用 `GMT+08:00`。
- 该版本生命周期 API 使用 `org.apache.shardingsphere.elasticjob.lite.lifecycle.api.JobAPIFactory`。
- Nacos 2.5.1 创建 Namespace 的接口可能直接返回布尔成功值，初始化脚本已处理。
- PostgreSQL 使用 SQL 初始化文件，避免依赖宿主机挂载脚本的可执行权限。

## 验证范围

已实测本机 Linux arm64 容器。Windows、Linux amd64、公司代理网络与离线镜像导入未在本机执行；移到公司电脑后可用同一条验证命令确认。

未演练执行中宕机的 failover、misfire、真实远端退款或跨系统事务。主演示关闭 failover / misfire，业务效果采用本地数据库流水。
